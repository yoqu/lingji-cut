# 目录树跨 tab 共享 — 实施规划

## 目标
把写稿工作台的目录树（`FileTreePanel` / `FileTree` / 纯工具函数）提取为可在「视频编辑器 / 资产 / 发布」复用的共享组件，配独立数据层 + 完整文件 CRUD + 各 tab 自定义展示与点击逻辑。

## 关键事实（已探明）
- `FileTree` + `TreeNode` + 4 个纯工具函数**已无 store 依赖**，只有 `FileTreePanel` 读 `useScriptStore`（取脚本专属的"全部/资源"子视图）。
- 4 个 tab 常驻挂载（`display:contents/none` 切换），都从 App 拿到 `projectDir={currentProjectDir}`。
- `fileEntries` 现由 `ScriptWorkbench` 加载（`readDirectory`→`setFileEntries`）并订阅 `onFileTreeChanged` 刷新；App 已统一 `startWatching`，但没加载 `fileEntries`。
- 主进程无文件 CRUD IPC；树当前只读（浏览+打开+拖出）。
- 原生右键菜单范式：`electron/workbench-tab-context-menu.ts` 导出纯模板函数，`main.ts` 用 `ipcMain.handle` + `menu.popup()` 接线。

用户已确认：**独立 store + App 加载** / **完整 CRUD** / **各 tab 自定义动作**。

## Phase 0 — 共享数据层

### 新建 `src/store/project-tree.ts`（`useProjectTreeStore`）
```ts
interface ProjectTreeState {
  projectDir: string | null;
  fileEntries: FileEntry[];
  isLoading: boolean;
  error: string | null;
  setProjectDir(dir: string | null): void;
  setFileEntries(entries: FileEntry[]): void;
  refresh(): Promise<void>;   // readDirectory(projectDir) -> setFileEntries
  setLoading(b: boolean): void;
  setError(e: string | null): void;
}
```
- `refresh()` 内部 `readDirectory(projectDir)`；`projectDir` 为空时清空。

### 新建 `src/hooks/use-project-tree-sync.ts`
封装 App 级同步：`currentProjectDir` 变化 → `setProjectDir` + `refresh()`；订阅 `onFileTreeChanged` → `refresh()`；卸载时取消订阅。
- 在 `App.tsx` 调用一次（App 已 `startWatching`，此处只补加载 + 树变更刷新）。

### 迁移读端
- `src/lib/mcp-readonly-handlers.ts`（L22/L135）：`useScriptStore.getState().fileEntries` → `useProjectTreeStore.getState().fileEntries`。
- `src/store/script.ts`：**移除** `fileEntries` / `setFileEntries`（保留 `fileTreeView`——脚本专属"全部/资源"切换）。
- `src/pages/ScriptWorkbench.tsx`：`fileEntries` 改从 `useProjectTreeStore` 取；删掉自己的 `readDirectory`/`onFileTreeChanged`/`setFileEntries` 逻辑；`refreshFileTree` 改调 `useProjectTreeStore.refresh()`。

## Phase 1 — 主进程 CRUD IPC + 右键菜单

### 新建 `electron/directory-tree-context-menu.ts`
纯模板函数 `createDirectoryTreeContextMenuTemplate({ relativePath, type, platform, onAction })`，菜单项：**新建文件夹 / 重命名 / 删除 / 复制路径 / 在 Finder(资源管理器)中显示**。沿用 `workbench-tab-context-menu.ts` 范式。

### 新建 `electron/project-tree-ipc.ts`（并在 `main.ts` 注册）
路径安全：所有操作先 `path.resolve(projectDir, relativePath)`，再校验结果**仍以 `projectDir` 为前缀**（防 `..` 穿越），否则返回错误。

| IPC channel | 行为 |
|---|---|
| `project-tree:create-directory` | `fs.mkdir(absPath, { recursive:false })`，EEXIST 报错 |
| `project-tree:create-file` | `fs.writeFile(absPath, content ?? '')` |
| `project-tree:rename` | `fs.rename(oldAbs, newAbs)`（含跨目录移动，但目标须在 projectDir 内） |
| `project-tree:delete` | `fs.rm(absPath, { recursive, force:false })`；删除前可由 renderer 先 confirm |
| `project-tree:show-context-menu` | 用模板构建 `Menu`，`menu.popup()`；选中动作经 `directory-tree-menu-action` 事件回传 renderer |

返回值统一 `{ ok: true } | { ok:false, code, message }`，renderer 据此刷新 + 报错。

### `electron/preload.ts` + `src/lib/electron-api.ts`
新增上述 channel 的桥接与类型；`window.electronAPI` 增加 `createDirectory / createFile / renamePath / deletePath / showDirectoryTreeContextMenu / onDirectoryTreeMenuAction`。删除/重命名后由 renderer 触发 `useProjectTreeStore.refresh()`（chokidar 也会推 `file-tree-changed` 双保险）。

## 风险与注意
- **路径安全**：CRUD 必须强制目标在 `projectDir` 内，防穿越/防越权删库。
- **重命名联动**：重命名正在编辑的文件需同步 script store 的 `openedFile`/dirty/conflict 键，否则状态错位。
- **删除确认**：目录递归删除是破坏性操作，renderer 先 `confirm` 再调 IPC。
- **双刷新**：CRUD 后 renderer 主动 `refresh()`，chokidar 也会推 `file-tree-changed`，需保证幂等（`setFileEntries` 覆盖即可）。
- **常驻挂载**：4 tab 都挂载，每个 tab 各自 `useProjectTreeStore` 选择器只读共享数据，不会重复加载（加载只在 App 的 sync hook 一次）。
- **MCP 兼容**：`mcp-readonly-handlers.ts` 改读新 store 后，行为不变（同样的 `fileEntries` 结构）。
